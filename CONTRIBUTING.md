# 🌟 Contributing to EduBridge

Thank you for your interest in contributing to EduBridge! 🎉  
We welcome meaningful contributions that improve the quality and usability of the project.

Please read the guidelines below carefully before contributing.

---

## 📌 Getting Started

1. **Fork** the repository to your GitHub account.
2. **Clone** your fork locally:
```bash
   git clone [https://github.com/your-username/EduBridge.git](https://github.com/your-username/EduBridge.git)
```
3. **Create a new branch** for your work:
```bash
   git checkout -b feature/your-feature-name
```
## 🏷️ Issue Selection

⚠️ **IMPORTANT:** All issues are created and managed by the Project Admin. **Contributors must request assignment before starting work.** Do NOT work on unassigned issues.

* Only **one contributor** will be assigned per issue.
* Choose issues based on your skill level by looking for these labels:
  * `easy`
  * `medium`
  * `hard`
  * `good first issue`

---

## 💻 Development Guidelines

* **Follow clean coding practices.**
* Write readable and well-structured code.
* Comment your code where necessary to explain complex logic.
* Ensure your changes do not break existing functionality.
* **Test your changes** thoroughly before submitting.

---

## 🔍 Pull Request Guidelines

* PRs **must** be linked to an assigned issue.
* Clearly describe what your PR does in the description.
* Keep PRs focused (strictly one issue per PR).
* Avoid unnecessary, formatting-only, or unrelated changes.
* *Note: Plagiarized or copied code will be strictly rejected.*

---

## 📝 Commit Message Guidelines

Use clear and meaningful commit messages that explain the specific change.

✅ **Good Examples:**
```text
Added quiz scoring functionality
Fixed authentication validation bug
Improved UI responsiveness
```
❌ Avoid vague messages like:
```text
fix
update
changes
```
## ❌ What Not to Do

🚫 **STRICT RULES:**
* **Do not** submit spam or low-effort PRs.
* **Do not** copy code from other repositories.
* **Do not** create issues without admin permission.
* **Do not** submit incomplete or broken features.

---

## ✅ Review Process

* All Pull Requests are reviewed by the Project Admin.
* Changes may be requested before final approval.
* Only approved and merged PRs are considered valid contributions.
* **Admin decisions are final.**

---

## 🤝 Code of Conduct

All contributors are expected to maintain respectful and professional communication. **Harassment, discrimination, or unethical behavior will not be tolerated.**
